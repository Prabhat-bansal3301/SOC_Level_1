# Boogeyman 1 – Phishing to Data Exfiltration Investigation (Email, PowerShell Logs, Network Capture)

**Scenario:** a user received a phishing email with an encrypted attachment. The investigation follows the attack in three layers:

| Layer | Evidence | Question it answers |
|---|---|---|
| **Email analysis** | The phishing email | How did the attacker get in? |
| **Endpoint analysis** | `powershell.json` (PowerShell script block logs) | What did the attacker run on the machine? |
| **Network analysis** | `capture.pcapng` | How did the attacker talk to the victim and steal data? |

Skills practised: phishing analysis, PowerShell log analysis, Linux command line, and traffic analysis.

## Tools Used

| Tool | Used for |
|---|---|
| **Thunderbird** | Opening the email and viewing the raw headers |
| **lnkparse** | Reading a Windows shortcut (`.lnk`) file without running it |
| **jq** | Reading and filtering JSON logs on the command line |
| **Wireshark** | Inspecting HTTP and DNS traffic in the capture |
| **TShark** | Command-line Wireshark, used to pull out thousands of packets quickly |
| **CyberChef** | Decoding Base64, decimal and hex data |
| **KeePass** | Opening the stolen password database to see what the attacker got |

## Attack Chain at a Glance

```text
Phishing email (encrypted Invoice.zip, password given in the email body)
        |
        v
Victim unzips it, opens a .lnk shortcut disguised as an invoice
        |
        v
.lnk runs PowerShell with a Base64 encoded payload
        |
        v
Payload downloads tools from the attacker's file hosting domain
        |
        v
C2 channel to a second domain (commands out, results sent back by HTTP POST)
        |
        v
Enumeration (Seatbelt) -> finds credentials -> reads Sticky Notes database with sq3.exe
        |
        v
Finds a KeePass database (.kdbx) and its master password
        |
        v
Exfiltration: file hex-encoded and sent out in DNS queries using nslookup
```

## Glossary

| Term | Meaning |
|---|---|
| **Mail relay service** | A third-party service that sends email on a sender's behalf. Attackers abuse these so emails look like they came from a legitimate provider |
| **DKIM-Signature header** | A signature added by the sending mail server to prove the email wasn't altered. It also names the signing domain, which can reveal the relay used |
| **List-Unsubscribe header** | A header that normally holds an unsubscribe link. It often points to the real mail service behind the message |
| **`.lnk` file** | A Windows shortcut. It can run a program with arguments, so attackers use it to launch PowerShell while looking like a document |
| **Script block logging (Event 4104)** | A Windows feature that records the actual PowerShell code that ran. The logs here hold it in the `ScriptBlockText` field |
| **Seatbelt** | A tool that collects security-relevant information about a machine (enumeration) |
| **SQLite / `sq3.exe`** | A lightweight database format. `sq3.exe` is a tool that reads SQLite files |
| **Sticky Notes** | Microsoft's notes app, which stores notes in a SQLite database. Users sometimes save passwords there |
| **KeePass / `.kdbx`** | A password manager. `.kdbx` is its database file, protected by a master password |
| **nslookup** | A built-in Windows DNS lookup tool, abused here to send data out |
| **DNS exfiltration** | Hiding stolen data inside DNS queries (see the tunnelling notes). Each query's subdomain carries a chunk of data |
| **Hex encoding** | Writing data as hexadecimal characters so binary files can travel as text |

## Part 1: Email Analysis

**Goal:** identify the sender, the victim, how the email was sent and what the attachment does.

| Question | How to find it |
|---|---|
| Sender and victim addresses | Open the email in Thunderbird and read the From and To fields |
| Relay service used | **More → View Source**, then read the **DKIM-Signature** and **List-Unsubscribe** headers. They name the third-party service |
| Attachment | `Invoice.zip`, encrypted (password protected) |
| Password | Stated in the **email body**. Attackers give it so the victim can open the file while email scanners can't |
| File inside the zip | A shortcut (`.lnk`) disguised with an invoice-style name |
| Encoded payload | Run `lnkparse <file>.lnk` and read the **Command Line Arguments** field |

**Why this works for the attacker:**
- A **password-protected zip** can't be scanned by most email security tools
- A `.lnk` file shows as a harmless shortcut, but its arguments launch PowerShell
- A **third-party mail relay** makes the message look more legitimate

**Check the payload:** decode the Base64 in CyberChef. PowerShell `-enc` payloads are normally **UTF-16LE** text, so use **From Base64**, then **Decode text (UTF-16LE)** if the output has gaps between letters.

## Part 2: Endpoint Analysis (PowerShell Logs with jq)

**File:** `powershell.json` (script block logs from the victim machine).

| Step | Command | Purpose |
|---|---|---|
| 1 | `cat powershell.json \| jq` | See the structure and which fields exist |
| 2 | `cat powershell.json \| jq '{ScriptBlockText}'` | Show only the **ScriptBlockText** field, which is the actual code that ran |
| 3 | `cat powershell.json \| jq '{ScriptBlockText}' \| grep sq3.exe` | Search for one keyword in the results |

**Tip:** `jq -r '.ScriptBlockText' powershell.json` prints each script as plain text, which is easier to read.

**What scrolling through ScriptBlockText revealed:**

| Finding | Meaning |
|---|---|
| **Two domains** | One for **file hosting** (downloads tools) and one for **C2** (commands and results) |
| **Seatbelt downloaded** | The attacker enumerated the machine |
| **`sq3.exe` used on a file** | A SQLite tool reading a file in the victim's user profile |
| **The file belongs to Sticky Notes** | The attacker went through the notes database looking for saved credentials |
| **A `.kdbx` file sent to an IP address** | The attacker stole a **KeePass** password database |
| **Data encoded as hex** | Prepared to be sent out as text |
| **`nslookup` used** | The transfer method was **DNS queries** |

**Reading logs in order:** the sequence of commands tells the story (download tools → enumerate → find credentials → steal the database). You need that order later to know which network packets matter.

## Part 3: Network Analysis (Wireshark and TShark)

Use what the logs gave you (the attacker's IP and domains) to filter the capture.

### The payload server
- Filter: `http && ip.addr == <attacker IP>`
- Right-click a packet → **Follow → HTTP Stream**
- The server's response headers show which **software** hosted the payload. It was a simple Python web server, a common quick way to share files

### C2 traffic
- The C2 channel sent **command output back using HTTP POST**
- Filter: `http.request.method == POST` (46 results here)
- Too many to read one by one, so use the order of events from the PowerShell logs to guess which packets matter

### Finding the KeePass master password
- The password was inside one of the POST requests
- Right-click the right packet → **Follow stream**, then copy the data
- It was written as **decimal numbers**. In CyberChef use **From Decimal**
- Each number is one ASCII character (for example `72` is `H`)

### Rebuilding the stolen file from DNS traffic
The attacker split the file into chunks and sent each one as a subdomain in a DNS query, so you have to put the chunks back in order.

- Filter in Wireshark: `dns && ip.dst == <attacker IP>`. It shows about **444 packets** with random-looking subdomains
- Doing this by hand would take forever, so use TShark

| Step | Command | What it does |
|---|---|---|
| 1 | `tshark -r capture.pcapng -n -T fields -e dns.qry.name \| grep "<exfil domain>"` | Lists every DNS query name for the attacker's domain |
| 2 | `... \| cut -f 1 -d "."` | Keeps only the part before the first dot, which is the data chunk |
| 3 | `... \| uniq` | Removes **consecutive** duplicate queries (repeats would corrupt the file) |
| 4 | `... > sensitive_file.txt` | Saves the chunks to a file |
| 5 | `cat sensitive_file.txt \| tr -d '\n' > file` | Joins everything into one string by deleting the newlines |
| 6 | CyberChef → **From Hex** | Converts the hex text back into the binary file |
| 7 | Save the output as `something.kdbx` | Rebuilds the KeePass database |
| 8 | Open in KeePass with the recovered master password | Shows the stolen contents, including a **credit card number** |

**Notes on the commands:**
- `-n` stops TShark resolving names, `-T fields -e dns.qry.name` prints only that field
- `uniq` only removes duplicates that are **next to each other**. If duplicates aren't adjacent, use `awk '!seen[$0]++'` instead, which keeps the first occurrence and the original order
- `cut -f 1 -d "."` means field 1 using `.` as the delimiter
- Make sure no leftover counts (from `uniq -c`) or blank lines remain, or the hex won't decode

## Key Takeaways
- **Email headers tell the real story.** DKIM-Signature and List-Unsubscribe can expose the relay service behind a message
- **Password-protected attachments are a red flag.** The attacker includes the password so email scanners can't open the file
- **A shortcut file can launch PowerShell.** `lnkparse` shows the hidden arguments without running anything
- **`jq` makes JSON logs readable.** Filter to `ScriptBlockText` first, then `grep` for keywords
- **Read the PowerShell logs in order.** They map the attacker's steps and tell you which network packets to inspect
- **Pivot between sources:** logs give you IPs, domains and filenames, and the packet capture gives you the details
- **DNS exfiltration** looks like many long, random subdomain queries to one domain. TShark plus `cut`, `uniq` and `tr` rebuilds the data
- **Different encodings in one case:** Base64 (payload), decimal (password) and hex (stolen file). Know the matching CyberChef recipe: **From Base64**, **From Decimal**, **From Hex**
- **Passwords in notes apps are risky.** One Sticky Note exposed the master password to the entire password database
- **Defences:** block or sandbox encrypted archives, block `.lnk` files in email, enable PowerShell script block logging, monitor unusually long or frequent DNS queries, and don't store credentials in plaintext
